cafaye exists so you never start a SaaS from scratch again: authentication,
tenancy, billing, notifications, media, and AI routing — production-grade,
self-hostable, and connected by typed contracts. It is an **organization, not a
single repository**: every service below lives in its own repo, versioned and
installable on its own. You can take the one you need rather than adopting the
whole platform, run the whole stack on your own infrastructure, and keep it
alive with the runbooks on this site.

## The services

| Service | What it does | Language |
| --- | --- | --- |
| [`identity`](https://github.com/cafaye/identity) | Users, sessions, accounts & tenancy, OIDC provider | Go |
| [`billing`](https://github.com/cafaye/billing) | Plans, subscriptions, prepaid credits, usage metering, processor webhooks in and out | Ruby |
| [`courier`](https://github.com/cafaye/courier) | Transactional email, push, and every outbound webhook — signed and retried | Elixir |
| [`darkroom`](https://github.com/cafaye/darkroom) | Signed media uploads, variants, S3 and Cloudflare R2 | Rust |

| [`parlor`](https://github.com/cafaye/parlor) | The app shell: production-ready frontend template + admin | Next.js |

## Why one language per service?

Because services have different jobs. `identity` holds the keys to everything —
it wants Go's discipline and static binary. `courier` fans out to thousands of
providers concurrently — that's the BEAM. `darkroom` pushes pixels — no GC
pauses wanted. `billing` is pure domain modeling — Ruby's home turf. `muse`
talks to models — Python's ecosystem is unmatched. And `parlor` is the web.
Polyglot by design, connected by typed contracts, never by shared code.

:::caution[Early development]
cafaye is **early**, and this site is written to say so rather than around it.
Of the ten `caf` subcommands, **five** do real work today (`version`, `doctor`,
`dev`, `contract lint`, `contract resolve`); the other five parse their flags and
return `not implemented in v0`. There is no hosted platform and **no broker** —
no service starts an outbox publisher loop, so an event is a row and nothing
more. Three of the seven services are built past their first milestone
(`darkroom` ships signed uploads and Cloudflare R2; `courier` ships outbound
webhooks over the Standard Webhooks spec; `guard` ships Redis-backed rate
limits), and three have a gap a reader will hit: **`identity` has no MFA**,
`muse`'s auth does not verify the token it is given, and **`guard` routes
nothing**. Every service page states plainly what is built and what is not, and
[Getting started](/getting-started/) runs the whole path end to end with the
commands that actually exist today.

**Most repositories also have no CI.** `kit`'s reusable workflow shipped but is
not yet callable from GitHub, so a green gate on eight of the thirteen
repositories rests on somebody having run the suite by hand. See [Running the
gates](/running-the-gates/).
:::
